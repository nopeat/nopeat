# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Numbers in this file are measurements, not estimates. Every one is reproducible
with the harness in `bench/`; see `docs/schema/bench-spec.md` for the protocol
and `bench/results/` for the raw output. Where a target is not met, the entry
says so and gives the number.

## [Unreleased]

## [2.1.1] - 2026-10-09

### Fixed

- The npm installer asked for asset names the release never published: it derived
  them from `process.platform` and `process.arch`, so it requested
  `nopeat-2.1.0-linux-x64.tar.gz` against a published
  `nopeat-2.1.0-x86_64-unknown-linux-gnu.tar.gz`, and a bare `.exe` against a zip.
- The cross builds did not install their targets, so three of the five release
  targets failed.
- `blake3` was a dependency of a function nothing called, and it needs a C
  cross-compiler.
- The coverage floor read the wrong column of the llvm-cov summary and failed a
  run at 82.19%.

### Changed

- The README documented `nopeat ./dist --mode csv`, which exits 2. CSV is a
  separate `--csv <FILE>` flag.

## [2.1.0] - 2026-09-30

### Fixed

- The README offered `npx nopeat` and `cargo install nopeat-cli`, and
  carried npm and crates.io badges, none of which resolves: neither package is
  published, and by this project's own release order the npm wrapper is spent
  last. The install section says so and builds from source instead, and
  `bench/harness/links.mjs` now refuses an offered install or a package badge on
  any front page while `repo-links.json` is still empty. A claim of availability
  is worse than a dead link, because a reader cannot tell whether the command
  failed or the project is lying. The badges and the two one-liners come back in
  the commit that fills the table in.

## [2.1.0] - 2026-09-30

First public release. The ingest, fusion, report, budget and CI areas are
implemented and measured; WASM and the WebGL renderer are not.

### Added

- **Streaming stats ingest** (`nopeat stats.json ./dist/stats.json`) for
  webpack and rspack, plus esbuild `metafile.json`. Modules enter the graph one
  at a time; the document is never materialised.
- **Size attribution** from disk: `parsed` (real bytes) and `gzip` (level 6) per
  asset, in parallel with rayon, with the declared `stat` size kept alongside
  rather than overwritten.
- **Source map v3 parsing** with a positional VLQ decoder, indexed map sections,
  path normalisation and tail attribution: bytes after the last mapping are
  credited to the last source rather than dropped.
- **The fusion join** — the part neither reference tool does. Module sizes are
  corrected to the map's attribution, and whatever does not reconcile becomes a
  diagnostic: *ghost code* (declared by the bundler, mapped by nothing) and
  *hidden code* (generated bytes that map back to no module).
- **A self-contained HTML report**: Canvas 2D squarified treemap, package /
  source / chunk dimensions, fuzzy search, light-dark-auto, no web fonts and no
  network requests. Reports over 2 MB of detail ship a companion `.data.js`
  loaded on demand, because `fetch()` cannot read a sibling file from `file://`.
- **Size budgets** (`nopeat.config.json`) over total bytes, per chunk or per
  package, each optionally on a named dimension. A breach exits 1 with `NPT0040`;
  a rule that matches nothing is an error, not a silent pass.
- **`--mode json` and `--mode csv`** for CI and BI consumers.
- **A build folder with no bundler metadata** (`nopeat ./dist`): the output
  and its source maps, which is what Vite, Rollup, Parcel and tsup give you by
  default. Sizes are measured rather than declared, so they are exact, and each
  source in a map becomes a module. Ghost code is defined against a declared
  graph, so this mode reports itself as undetectable (`NPT0051`) instead of the
  reassuring zero it would otherwise print.
- **Parity harness** against `webpack-bundle-analyzer` on real webpack builds.
- **Performance charts** generated from the records in `bench/results/`, with a
  gate that fails the build if a label overlaps, is clipped, or arrives below
  9 px at README width.

### Measured

| target | input | limit | result |
|---|---|---|---|
| B1 | 363 MB stats, 154,379 modules | ≤ 2 s, ≤ 200 MB | **1.39 s / 157 MB** |
| B3 | the same, full pipeline + 1,500 assets | ≤ 5 s, ≤ 200 MB | **1.75 s / 156 MB** |
| B4 | 1 GB stats, 445,602 modules, full pipeline | ≤ 15 s, ≤ 400 MB | **5.17 s / 376 MB** |
| B5 | 36.5 MB source map, 50k sources | ≤ 1 s | **209 ms / 67 MB** |
| B8 | 1 GB stats + 36.5 MB map, fused | < 500 MB | **3.57 s / 137 MB**, coverage 100% |
| B9 | parity vs WBA, real webpack builds | ≤ 0.1 % | **0 ppm** on assets and modules |

Reference points on the same inputs: `webpack-bundle-analyzer@4.10.2` 63.6 s /
2,295 MB for the 363 MB fixture; `source-map-explorer@2.5.3` 562 s / 642 MB for
the 50k-source map. The full pipeline is 36x faster and 15x smaller than WBA on
the stats fixture; source map attribution is 2,690x faster than SME at 50k
sources.

**Not met:** B2, the 1 GB ingest-only target of ≤ 3 s, measured 4.40 s. Memory is
comfortable at 350 MB. The gap is `serde_json`'s DOM cursor over a 445,602-element
module array.

**Unverified:** B10, report first paint and interaction, because CI has no
browser. Report generation is measured instead (1.56 MB and 1.27 s at 154,379
modules).

### Fixed

Bugs found by the benchmarks, each with a regression test:

- Folder ingest read only the top level of `dist/`. Vite puts every file under
  `dist/assets/`, so the tool reported one asset for a real vite build. Both the
  asset walk and the source map discovery now recurse, and a map's name is its
  path relative to the folder, so `assets/index-a1b2c3.js.map` joins the asset
  it describes instead of matching nothing.
- A source map that failed to parse was dropped in silence. The report then
  showed a lower coverage figure with no explanation, which reads as a build
  that shipped no source maps rather than a broken map. Unreadable maps are now
  named on stdout with the parse error.
- A source file compiled into two chunks was counted twice in the attribution
  count and its bytes were overwritten rather than summed, so its size depended
  on which map was read last. The summary could read `2/1 modules attributed`.
- Chart regeneration was not reproducible: `<dc:date>` recorded the run time and
  matplotlib's element ids are random, so regenerating always produced a diff
  and the CI gate that depends on it could never pass.

- `detail_payload` built a `serde_json::Value` per module before serialising —
  550 MB of heap for 154,379 modules. B3 went from 3,052 ms / 670 MB to
  1,753 ms / 156 MB.
- `ghost_modules` held one entry per unmapped module (445,602 of them, 47 MB),
  for something documented as a summary. The lists are now bounded samples that
  report what they dropped; counts and byte totals stay exact. The hidden byte
  total was additionally summed *after* truncation, so it under-reported.
- The module/source join scanned every source for every module: 2.5 billion
  comparisons, 73.8 s on B8. Now a suffix index built once per asset, 4.94 s,
  with a test asserting the index and the scan agree on the awkward cases.
- The treemap's asset lookup and the ghost classifier were both
  O(modules × assets).
- Package references are interned: 445,602 modules shared 400 packages' worth of
  strings, which cost ~70 MB on the 1 GB fixture.
- The companion `<script src>` was written with a literal placeholder that
  nothing substituted, so every report over the inline limit shipped a detail
  file no report ever loaded.
- `--mode json` lost the module table during report payload slimming; and the
  module table was then re-added to the HTML payload, putting every report back
  to 55 MB.
- VLQ segments were split on every colon instead of the first.
- Bytes after a map's last mapping were dropped rather than credited.
- A readable and a minified map for the same asset were both counted, inflating
  attribution. Maps are now scoped per asset.
- JSON inputs with a UTF-8 BOM failed to parse, which Windows editors add by
  default.

### Security

- `unsafe_code` is forbidden workspace-wide.
- The npm package verifies `checksums.txt` before writing or executing a
  downloaded binary, and refuses to install one whose checksum does not match.
- The report renders text to Canvas and never to `innerHTML`; the shell escapes
  `</script` in its data island.
