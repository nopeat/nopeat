# Security Policy

## Supported versions

Fixes land on `main` and in the next release;
there are no long-term support branches yet.

| version | supported |
|---|---|
| 2.1.x | yes |
| < 2.1.0 | no |

## Reporting a vulnerability

**Do not open a public issue.** Use GitHub's private reporting
("Security" → "Report a vulnerability") on the repository, or email the
maintainers listed in `Cargo.toml`.

Please include: what you found, the input that triggers it (a stats file or
source map is ideal — synthetic fixtures are fine and appreciated), the impact,
and whether you have a proof of concept.

Expect an acknowledgement within 72 hours and an assessment within 7 days. We
will tell you when a fix lands and credit you in the release notes unless you
ask us not to.

## Threat model

Nopeat reads untrusted build output and renders it. The interesting surfaces
are:

| surface | risk | what we do |
|---|---|---|
| `stats.json` / `*.map` / `metafile.json` parsing | a hostile file could exploit a parser bug, or a crafted payload could exhaust memory | `unsafe_code` is forbidden workspace-wide; parsers are streaming and bounded; input size is not capped, so a huge file is a DoS on *your* machine, not a remote one |
| the HTML report | a build output containing `<script>` must not execute | the shell loads its data as JSON inside a `<script type="application/json">` tag and escapes `</script`; the treemap renders to Canvas with text drawn, never to `innerHTML` |
| the npm package | a binary is fetched over the network and executed | `checksums.txt` is verified before the binary is written, and a mismatch aborts the install |
| CI | a PR must not be able to publish a release | releases only run from a pushed tag, and require the workspace version to equal the tag |

Known limits, stated rather than hidden:

- **No size limit on input.** Nopeat will read a 40 GB stats file if you ask
  it to. The memory target is a *constant* overhead, not a cap.
- **The report is HTML with inline data.** It opens from `file://`, which is
  what makes it work by double-clicking. A report is only as safe as the machine
  that generated it — do not open an untrusted report on a machine where a
  script execution would matter.
- **No sandboxing.** Parsing is in-process. A native crash in a parser is a
  crash, not a contained failure. Fuzzing (`cargo fuzz`) covers the source map
  decoder; the stats parser is not yet fuzzed.

## What is out of scope

- Vulnerabilities in `serde_json`, `rayon`, `flate2` or any dependency. Report
  those upstream; we will bump the dependency.
- Denial of service caused by pointing the tool at a deliberately enormous file
  on your own machine.
- Reports generated by a modified or unofficial build.
