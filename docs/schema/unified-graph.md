# Contract: the unified bundle graph

Status: **frozen for Phase 1**. Owner: maintainers (model). Changes need an ADR +
`schema_version` bump + a migration note in `08-roadmap.md`.

Companion files: [`report-schema.json`](report-schema.json) (wire format),
`crates/nopeat-core/src/model.rs` (the code that mirrors it).

## 1. Why one graph

The two tools Nopeat replaces each carry half the truth:

- `webpack-bundle-analyzer` knows the **dependency structure** (modules, chunks,
  who pulled what in) but only *estimates* sizes.
- `source-map-explorer` knows the **real byte attribution** (which original
  source produced which generated byte) but has no dependency graph.

Neither can answer "this 40 KB chunk: which npm package is responsible, and how
much of it survives minification?". The unified graph is that answer, and it is
the product.

## 2. Nodes and join keys

```
asset ──contains──▶ chunk ──contains──▶ module ──maps_to──▶ source file
                                          │
                                          └──from_package──▶ npm package
```

**Module join key** (the single most important rule in this document; the whole
fusion engine hangs off it):

1. `stats.modules[].identifier` when present — the only field webpack keeps
   stable across builds.
2. otherwise `"{chunk_id}:{name}"` — the same `name` may legally appear in
   several chunks, so the chunk is part of the key.
3. never a hash of mutable content; the key must survive a rebuild with no
   source change, otherwise every report would show "everything is new".

A source file is joined to a module by **normalised path suffix matching**,
because bundlers rewrite absolute paths and the map's `sources` entries are
relative to the map location. Normalisation rules, in order: strip the map's
directory prefix, convert `\` to `/`, drop a leading `./`, and finally match on
the longest common suffix. Anything that cannot be matched is reported as a
`hidden_source` rather than being dropped silently.

## 3. Size dimensions

| dimension | source | trust |
|---|---|---|
| `stat` | the bundler's own numbers | estimate; wrong whenever minification, concatenation or a `null` byte in `size` kicks in |
| `parsed` | bytes of the emitted file | exact for "how big is the file" |
| `gzip` | gzip level 6 of the emitted file | exact; **level is part of the contract** (see `sizes::gzip_size`) |
| `attributed` | source map mappings | ground truth per original source |

`SizeSet::effective()` resolves in the order `attributed > parsed > stat`, and
`totals.size_dimension` records which one the report used. A report must never
mix dimensions silently: when only some assets are mapped, the whole report
falls back to `parsed` (see `fusion::choose_dimension`), because a report that
looks smaller than reality is the worst failure mode this tool has.

## 4. Invariants

Checked by the CLI before any output is written; a violation is an error, not a
warning, because it means the join keys are wrong.

1. `sum(module.effective()) == totals.total_size` within **1,000 ppm (0.1%)**
   when `size_dimension == attributed`.
   Implemented as integer arithmetic in `UnifiedBundleGraph::check_size_invariant`.
2. every `fusion.ghost_modules[].module` exists in `modules`.
3. `fusion.total_attribution_delta == sum(module.attribution_delta)`.
4. `gzip` is only ever reported when the asset bytes were actually available;
   a missing measurement is `0`, never an estimate.

## 5. Diagnostics instead of silent behaviour

Every degradation is a `Diagnostic` with a stable `code`:

| code | meaning |
|---|---|
| `NPT0001` | stats file has no `modules` array (dev-server export?) |
| `NPT0002` | chunk references a missing asset |
| `NPT0010` | source map version is not v3 |
| `NPT0011` | source map has no `sourcesContent`; code drill-down unavailable |
| `NPT0020` | ghost module detected |
| `NPT0021` | hidden generated bytes detected |
| `NPT0030` | gzip level differs from the contract level 6 |
| `NPT0040` | budget breached (paired with exit code 1) |
| `NPT0042` | size invariant violated (paired with a non-zero exit code) |
| `NPT0050` | the requested size dimension is not measurable, so another one is reported instead (the code says which, and which direction the change goes) |
| `NPT0051` | a folder input carried no bundler metadata: sizes are measured and sources are attributed from the maps, and ghost code is reported as undetectable rather than as zero |

## 6. Determinism

Given the same inputs, the CLI must produce byte-identical JSON:

- collections that reach the output are `BTreeMap`/`Vec` sorted by key;
- no timestamps, no absolute paths, no HashMap iteration order in the output;
- the report HTML embeds the JSON payload as-is, so parity tests can diff both.

This is what makes `parity-and-testing.md` possible at all.
