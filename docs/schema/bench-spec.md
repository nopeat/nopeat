# Contract: benchmark harness

Status: **frozen for Phase 1**. Owner: maintainers. Code in `bench/`, CI job in
`.github/workflows/bench.yml`.

Nopeat's credibility rests on numbers other people can reproduce. This
contract exists so a benchmark run is a command, not an anecdote.

## 1. Two fixture classes, never mixed

| class | what | used for |
|---|---|---|
| **real** | small, famous, permissively licensed projects we build ourselves: `preact`, `marked`, `chalk`, `dayjs` (+ `p-limit`, `nanoid`, `ms`, `mitt`, `ufo`, `h3` for smoke tests) | correctness, parity, CI, realistic sizes |
| **synthetic** | generated by `bench/harness/gen-*.{js,rs}`: 381 MB / 1,049 MB stats with 160k-442k modules, `.map` with 10k+ sources | scale, memory ceilings, regression floors |

Results from the two classes are **always reported in separate tables**. A
synthetic 1 GB number must never be presented as "a real project needs 1 GB".

Every fixture is recorded in `bench/fixtures/manifest.json`: repo, commit, license,
build command, artifact paths, artifact sizes, content hash. Fetching is
`bench/fixtures/fetch.ps1` (Windows) / `fetch.sh` (POSIX), clones with
`--depth 1` and records the exact commit.

## 2. Measurement protocol

For every run we record:

- `wall_ms` — end to end, including process start
- `peak_rss_mb` — sampled at 100 ms, reported as the max
- `phase_ms` — the breakdown the tool itself emits:
  `scan → parse → attribute → fuse → report`

Rule: **a phase we do not measure must not be claimed**. The reference numbers
we already have (`docs/en/evidence.md`) show why: `webpack-bundle-analyzer`
spent 0.94 s reading and parsing a 381 MB stats file and the remaining ~60 s in
its own analysis, which is the part Nopeat has to reproduce.

Sample size: 3 runs, report the median, discard the first run on a cold file
cache and say so. Same machine, same power profile, nothing else running.

## 3. Targets (regression floors, checked by CI)

| # | scenario | target | status |
|---|---|---|---|
| B1 | stats 381 MB / 160,728 modules, parse only | ≤ 2 s, ≤ 200 MB | prototype measured 0.99 s / 17 MB |
| B2 | stats 1,049 MB / 441,976 modules, parse only | ≤ 3 s, ≤ 400 MB | prototype measured 2.78 s / 59 MB |
| B3 | 400 MB full pipeline (parse + attribute + report) | ≤ 5 s, ≤ 200 MB | **unverified — sizes** |
| B4 | 1 GB full pipeline | ≤ 15 s, ≤ 400 MB | **unverified — sizes** |
| B5 | `.map` 50 MB / 10k sources, parse + attribute | ≤ 1 s | **unverified — source maps** |
| B6 | `source-map-explorer` on the same `.map` (baseline) | any number, but must be recorded | **unverified — the source-map-explorer baseline** |
| B7 | gzip of 25,600 assets | — | rayon prototype: 2,177 ms → 342 ms (6.4x) |
| B8 | fusion memory on 1 GB stats + 50 MB map | < 500 MB peak | **unverified — fusion** |
| B9 | parity diff vs wba / sme | ≤ 0.1 % (ordering only) | **unverified — parity** |
| B10 | report: 10k modules, first paint / interaction | < 2 s / > 30 fps | **unverified — report** |

Any target that gets missed is recorded as missed. Benchmarks are never
quietly retargeted; a change needs an ADR.

## 4. Reference baselines we already measured

Recorded here so a regression is obvious, machine and date included
(Windows, node 24.18, python 3.12, rustc 1.97):

| tool | input | wall | peak RSS |
|---|---|---|---|
| webpack-bundle-analyzer 4.10.2 | stats 381 MB | 61.4 s | 1,985 MB |
| webpack-bundle-analyzer 4.10.2 | stats 1,049 MB | 176.3 s | 1,437 MB |
| node `JSON.parse` floor | stats 381 MB | 0.94 s | 919 MB |
| Nopeat streaming prototype | stats 381 MB | 0.99 s | 17 MB |
| Nopeat streaming prototype | stats 1,049 MB | 2.78 s | 59 MB |

The `#492` crash ("Cannot create a string longer than 0x1fffffe8") did **not**
reproduce on node 24: the V8 string ceiling moved. The memory wall is still
real (1.4-2.0 GB and growing linearly), so we do not claim the crash, only the
ceiling.

## 5. Result format

One JSON per run, written to `bench/results/<date>-<fixture>-<tool>.json`:

```json
{
  "fixture": "preact@10.29.8",
  "fixture_class": "real",
  "tool": "webpack-bundle-analyzer@4.10.2",
  "input_bytes": 401_418_752,
  "wall_ms": 61_355,
  "peak_rss_mb": 1_985,
  "phase_ms": null,
  "notes": "stats-only path; bundles not parsed"
}
```

`phase_ms` being `null` is a valid, useful value: it records that we did not
measure that breakdown, which is exactly the honesty rule the project's
evidence log depends on.

## 6. CI behaviour

`bench.yml` runs on every PR that touches `crates/nopeat-core/src/{stats,sizes,fusion,sourcemap}`:

1. B1/B2 on the synthetic fixtures, 1 run, compare against the floor;
2. parity (B9) on the real fixtures;
3. uploads the JSON results as a build artifact.

It does **not** gate on absolute wall time (CI runners are noisy); it gates on
memory ceilings and on parity, and it publishes timings for humans. A dropped
memory ceiling is a regression we care about; a noisy 1.2x on wall time is not.
